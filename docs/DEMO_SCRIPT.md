# 演示脚本

本文档用于面试或项目展示时快速走通 lawyerAgents 主线。建议按顺序演示，不要临场发散到未完成的能力。

## 演示前准备

后端：

```powershell
uv run python run.py
```

前端：

```powershell
cd frontend
pnpm install
pnpm run dev
```

打开前端页面后，确认后端健康检查通过：

```text
http://localhost:9000/api/health
```

## 1. 法条问答

输入：

```text
试用期最长可以约定多久？
```

观察点：

- RAG 过程面板显示分类、Query Rewrite、BM25、向量检索、RRF、Rerank、上下文扩展、引用校验和生成回答。
- 回答包含明确法律依据。
- sources 卡片展示 `law_name`、`article_no`、`source_level`、`authority_weight` 等信息。

讲法：

```text
这个项目不是直接让模型回答，而是先用 BM25 处理法条编号和关键词，再用向量召回口语化表达，通过 RRF 融合和 Rerank 精排控制最终上下文。回答后的 sources 会被统一标准化，并带有权威等级，便于检查答案依据。
```

## 2. 跨领域问答

输入：

```text
公司高管把员工工资款挪走了，员工能劳动仲裁还是报警？
```

观察点：

- 系统识别到复合问题时，会进入多域协作链路。
- 可以观察劳动、刑事或相关领域的拆解与合并结果。
- 最终回答区分劳动权益救济和可能的刑事报案路径。

讲法：

```text
跨领域问题如果只按单一领域检索，很容易漏掉另一条处理路径。这里用 LangGraph 做多域拆解，并行检索后再合并生成，让劳动仲裁和刑事报案两个方向都能进入上下文。
```

## 3. 案情分析

输入：

```text
我在一家公司工作两年，一直没有签劳动合同。公司每月发工资 8000 元，最近因为我要求补签合同和补缴社保，老板口头通知我不用来了，也没有支付最后一个月工资。我有工资流水、聊天记录和考勤截图，想知道我能主张什么。
```

观察点：

- 页面不只展示 Markdown 报告，还展示结构化案情分析卡片。
- 重点查看案情摘要、风险等级、法律关系、claims、证据清单、缺失信息和下一步建议。
- done 事件中应有 `analysis_result` 和 `case_state`，后续文书生成可以复用。

讲法：

```text
案情分析不是一大段不可复用的 Markdown。后端要求模型在报告后追加 JSON，并做容错解析；即使 JSON 失败也保留 Markdown。结构化结果可以让前端做卡片展示，也能给后续劳动仲裁申请书生成复用。
```

## 4. 劳动仲裁申请书

输入：

```text
帮我基于刚才的案情写一份劳动仲裁申请书。
```

如果系统追问缺失字段，可以补充：

```text
申请人张三，身份证号暂时不填，电话 13800000000。公司叫上海示例科技有限公司，地址是上海市浦东新区世纪大道 100 号。我是 2024 年 3 月 1 日入职，月工资 8000 元，2026 年 6 月 30 日被口头辞退。
```

观察点：

- 字段不足时返回缺失字段和最多 3 个追问，不直接生成最终文书。
- 字段足够时展示劳动仲裁申请书 Markdown 预览。
- 缺失字段使用 `【待补充】`，不编造身份证号、地址、工资、日期等事实。
- done 事件包含 `document_type`、`extracted_fields`、`missing_fields`、`document_markdown` 和 `can_export`。

讲法：

```text
文书生成没有让 LLM 一把梭，而是先做案情状态提取、字段槽位检查和缺失追问。核心字段不足时暂停生成；字段足够后用稳定模板输出 Markdown 草稿，缺失信息保留占位，避免编造事实。
```

## 5. 评测回归

命令：

```powershell
uv run python eval/run_eval.py
```

观察点：

- 生成 `eval/results.jsonl` 和 `eval/report.md`。
- 报告包含总览、分领域、分难度、失败归因、高延迟样例和优化建议。

讲法：

```text
评测不依赖外部 LLM Judge，而是用 expected_laws、expected_articles、citation_supported_rate、domain_hit 和 latency 做规则化回归。它能定位问题出在召回、引用、领域分类还是延迟。
```

## 收尾讲法

```text
这个项目的重点不是堆法律问答功能，而是把法律 RAG 的关键工程问题做成闭环：可召回、可引用、可拆解、可复用、可观测、可评测。当前阶段主线收敛在法条问答、案情分析和劳动仲裁申请书生成，后续扩展文书类型或企业网关都可以沿着这条链路继续做。
```
